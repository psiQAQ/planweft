# PLAN-0002：交接与文档维护基线

状态：Completed；需求来源：用户于 2026-09-07 授权按下一步建议实施，并允许尝试本机 Agent 镜像，使用后清理本轮资源。

## 目标与完成标准

在基础提交 `affbff9` 上，让无旧会话的独立读者回答项目目标、实际能力、阶段与授权、文档职责、引用/创新 review、个人 override、参考恢复和迁移门槛八类问题；对照仓库证据逐项判断。随后处理实际发现，完成引用、review、验证和交接，依据结果决定首个工具功能是否必要。本轮不预设必须写 CLI。

## 计划

- [x] 检查 Git 和本机 Docker 资源，冻结受跟踪文档快照；已有书籍和个人会话不进入容器快照。
- [x] 使用无历史 fork 的独立 subagent 做只读基线；记录问题、回答及依据。
- [x] 尝试现有 Codex 镜像的新会话，区分环境失败与阅读失败。
- [x] 依据实际发现完成一次文档维护，更新资料和引用。
- [x] 进行独立依据 review、受影响问题回测和本地静态验证。
- [x] 记录最小功能采用/暂缓决定，清理本轮容器及临时认证副本，完成本地提交。

## 约束与验证

参考：P-06 `doc-coauthoring` 的 `Stage 3: Reader Testing`、R-04 自包含交接、R-18 预期/实际结果。题目和判定是本地实验选择，不是标准 benchmark；单次通过不说明所有 Agent 均可靠。CLI 与模型版本、上下文边界、读取轨迹、实际结果分别记录。

Docker 使用已有镜像，仅创建本轮命名且带标签的临时实例；不启动、删除已有服务，不接入原实验的共享记忆。通过空白用户目录、非恢复调用及只读文档快照排除旧对话文件，认证仅用于对应 Codex 服务。结束后核对临时容器不存在，保留已有镜像。

本轮 Windows 产品行为仍需待实际原型与可用环境验证；没有原型时记录 Not Run。结果写入 reproduction 与 review，再回填本文。若无法运行容器，不将镜像存在或 `--help` 成功写成 Agent 行为通过。

## 结果与下一步

两个独立新读者均正确回答八项核心问题。容器先经历网络超时、嵌套 namespace 不兼容，调整本轮临时运行方式后读取成功；完整范围见 [REP-0002](../reproduction/0002-handoff-maintenance-baseline.md)。这不是全部客户端或双平台通过。

实际维护已澄清首页阶段、更新当前导航、补清旧 ADR 的验证范围、标明历史检查的适用快照，并收录本次实际使用的 R-20。根据当前证据，[ADR-0004](../adr/0004-defer-product-cli-after-baseline.md) 决定本轮暂缓 CLI；只读检查入口保留为候选。

独立依据 review 与三组受影响问题回测通过，见 [REV-0002](../reviews/0002-handoff-maintenance-review.md)。本轮无阻断项；临时容器、认证副本及实验临时文件已清理，原镜像和已有容器保留。结果随本计划同一逻辑提交保存，没有推送。

下一步在实际项目维护中观察重复漏检或核对成本，出现具体问题再比较现有检查工具与只读检查入口。没有产品原型，因此本轮不运行产品双平台测试，不切换自管理体系。
