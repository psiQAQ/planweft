# 创新与资料未覆盖的设计

截至 0.3.0，本仓库有已实现的工作流扩展、确定性分发、宿主适配与验证工具，但没有据先例检索和独立审查确立的方法首创声明。README 中的“原创实现”指本地编写的扩展与组合贡献；文件规划、ADR、冷读和生成分发本身各有已有方案。实现归属见 [引用台账](design-references.md) 和 [补丁清单](../overlays/program-design/PATCHES.md)。目录命名、引用台账和个人偏好分离仍属于需求/本地取舍。

## 新想法的处理

先说明实际问题和最小验证，再检索官方文档、GitHub 实现及已收录子模块。检索组合使用问题描述、机制名称和近义词，记录日期、查询与范围；沿相关结果检查具体源码。找到先例后补入 [资料索引](reference/README.md)，并更新 [引用台账](design-references.md)。

如果没有找到足够相近的实现，新增下表记录。只能说“本次检索未找到”，不能把未检出写成不存在，也不能以此绕过必要性审查。

| 字段 | 应记录的内容 |
| --- | --- |
| ID、状态、目标文件 | 候选/验证中/采用/放弃；对应本仓库文件和需求 |
| 问题与已有方案不足 | 可观察的问题；为何普通文档或现有实现不足 |
| 检索证据 | 日期、查询词、搜索渠道/范围、打开的来源及结论 |
| 最接近的实现 | 本地参考位置、差异及适用限制 |
| 新设计与成本 | 超出资料的部分、维护负担及最小实现 |
| 验证与退出条件 | 如何证伪、何时删除或退回已有方案 |
| 独立 review | 来源核对、必要性结论、报告位置 |

### RC14 后续假设：探索前形成项目入口集合

Claude/Pi 的 RC14 实际记录均先成功加载完整 Skill、获得准确资源根，随后仍探索宿主或安装器目录并读取配置。因此不能继续把失败解释为 Skill 不可发现或定位信息缺失。把主入口第一步改为具体动作：在已有回复列出用户路径及根指令/README形成的初始项目入口，先读这些入口，再依据相关文档链接或实现/测试关系扩展；包资源保持独立的宿主已提供根。明确授权维护宿主配置的任务仍可纳入，不硬禁某些平台目录，不新增记录文件、自动写入 hook 或权限授予机制。

这是对 RC14 Claude/Pi 独立审查的可证伪本地干预，不是成熟上游能力或权限沙箱。待用原任务、原模型和新准确归档验证“先确定入口再探索”的实际顺序；不得无变化重试挑选成功，也不能以不存在检测到的直接Read反例证明所有shell/间接读取合规。记录抄写、遗漏错误和最终否认已发生越界的问题仍需独立处理。

RC15 复核补充：初始入口集合自身先受用户明确读取范围筛选，根说明并非无条件必读。DSH RC14 的 `env | grep` 虽未把其他变量值返回给模型，仍先枚举完整环境；新增双语按准确名称调用 `os.getenv` 的诊断示例，禁止以输出过滤冒充不枚举。该示例是任务级查询方式，不改变进程继承环境，离线用拒绝迭代与无关键的映射验证；真实新包遵循情况仍 Not Run。
