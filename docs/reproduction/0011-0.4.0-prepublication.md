# 0.4.0 稳定版预发布验收

本记录绑定尚未发布的唯一 `planweft-0.4.0.tgz`。归档由干净内容提交 `aa23df40f9ec8eaed05aa4fbf6f4f0011709995b` 使用发布 workflow 固定的 Node `24.20.0` / npm `11.11.0` 生成，SHA-256 为 `e611338a619adabb0ba943d75460a01d83e4670dbe7d69f5d1050a1c1467c132`。后续只允许提交不进入 npm 归档的验收附件；发布前必须在相同 packer 环境重建并证明归档逐字不变。本记录不是 npm 发布或 GitHub Release 已完成的声明。

## 首次发布尝试与纠偏

首次本地预审错误地使用 Node `22.22.1` / npm `9.2.0` 生成 SHA-256 为 `438f164a065e2b57469910580baee3c00aaeac92f1c2c831d1223343bfdb7e4c` 的 gzip 字节。OIDC workflow `34430655159` 在任何 npm 写入前由准确归档检查拒绝：workflow 的 Node `24.20.0` / npm `11.11.0` 重建结果是本记录绑定的 `e611…c132`。两个归档解压后的 tar 流 SHA-256 均为 `b195ce9c9d1a11590e456c613cc22636ab3a30ed118089e55e2036864085b1d0`，说明差异来自 packer/gzip 字节而不是包内容；失败后 npm 仍无 `0.4.0`，`next` 仍为 `0.4.0-rc.15`，`latest` 仍为 `0.4.0-rc.1`。

该问题按基础设施/夹具错误处理，并只执行一次纠偏重试。不得复用的准确产物、五宿主安装/卸载、用户文件保护、实际 Skill 读取，以及 Codex/Pi 有界模型工作流均在 canonical 归档上重新执行；结果与首次预审一致。Codex 开启/关闭配对的两个语义失败也原样保留，未再次重试。workflow `34430655159` 的失败和旧归档摘要作为审计历史保留，但不再作为发布候选或当前 acceptance 的依据。

## 已知限制

`LIMIT-CODEX-TRACE-INCOMPLETE`：预先声明的 Codex 开启/关闭 gate 配对原样保留两个 `Failed`。关闭场景没有进入 gate，模型只返回 `STOP_PROBE`，没有工具调用、额外续跑或项目变更，会话、卸载和容器清理均正常；但原生 trace 在 EOF 仍有未完成 syscall，因此 `trace_complete=false`。开启场景的 trace 完整且 gate 读取已归因，但负控不完整使配对断言不能通过。该结果不改写为 Passed，也不追加模型重试；它限制的是实验性的真实 autonomous/gated 停止声明，不推翻已通过的离线 cap/stall/关闭回归或正式核心能力。

Claude、OpenCode 与 DSH 的本轮自动维护、冷读、上下文注入、恢复和真实停止场景均按发布计划保留 `Not Run`，原因是避免用重复模型运行追求全绿；其历史结果和限制继续有效。远端 registry 生命周期、新会话加载及 promotion 审查必须在 `next` 发布后产生，预发布阶段保持 `Not Run`。
