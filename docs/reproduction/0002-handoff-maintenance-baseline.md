# REP-0002：新读者交接与实际文档维护

日期：2026-09-07；基线：`affbff9`。本轮是有限问题集上的行为观察，不是跨模型 benchmark，也不构成自管理迁移验收。

## 输入与判定

读者没有接收旧对话；从 README.md、AGENTS.md 开始按需读取仓库，提供相应文件及行号。八项问题如下，预期在基线快照上确定：

| ID | 问题 | 基线预期 |
| --- | --- | --- |
| Q1 | 项目目标和当前实际交付是什么？ | 面向 Agent 的文档管理；交付参考与 Markdown 治理基础 |
| Q2 | CLI/Skills/hooks 已实现吗，平台实测范围？ | 产品尚未实现；Linux 文档/Git 静态及恢复检查已记录，双平台产品 Not Run |
| Q3 | 当前阶段、下一步及授权范围？ | 基础阶段结束；先验证真实问题与最小能力，没有自动开始候选产品的授权 |
| Q4 | 四类常规文档为什么分开？ | 规格是目标、计划是进度、ADR 是取舍、reproduction 是观察证据 |
| Q5 | 没有先例如何处理，谁 review？ | 先检索，再引用或登记有限检索/验证/退出条件；独立 subagent，主 Agent 处理 |

| Q8 | 何时切换自管理？ | 生命周期、证据、交接及内容/历史/链接完整，独立 review、新迁移 ADR 与回退 |

每项要求核心结论正确、可定位依据、不把未知状态当作已验证；缺少材料或工具不可运行单独记为未完成，不计为文档答错。主 Agent 依据基线文件逐项检查回答。题目本身指出需关注的领域，结论不代表无提示任务发现能力。

## 读者 A：无历史 fork 的 subagent

调用 `cold_reader_baseline` 时使用 `fork_turns=none`；只允许读取本仓库，不访问 memory 或其他会话，不运行第三方工作流。宿主系统指令仍存在，不声称模型没有一般背景知识。读取 15 份 Markdown 及 `.gitmodules`，HEAD 为 `affbff9`，Git 状态干净。

实际：Q1～Q8 **Passed（8/8）**。读者区分了当前产品状态与历史检查，明确没有重跑历史验证；未发现阻断交接的矛盾。输出要点由主 Agent 汇总：

- Q1/Q2：基础交付完整，第一方文件清单为文档；参考项目的工具不算本项目能力。
- Q3/Q4：基础工作结束；后续先找真实问题，文档按目标、进度、理由和证据分工。
- Q5/Q6：新机制先检索，依据审查与主 Agent 处理分工明确；个人文件只是差异稿，真实加载尚未验证。
- Q7/Q8：恢复固定版本且不运行研究材料；迁移门槛已接受但迁移未发生。

实际发现：README“当前处于基础阶段”与计划“阶段完成”有轻微措辞张力；ADR-0001 将新读者检查列为验证方式，而旧 review 只有依据审查，没有单独冷读证据。读者没有把 143/146 两个历史链接数量视为矛盾，因为原记录注明了时间范围。

## 读者 B：既有镜像中的 Codex CLI

镜像：`agent-memory-lab/codex:local`，ID `sha256:aa46e31c71577eb37c1e1d856427d9d159ddd5a41aa92472af722838b1c3a159`；Linux/amd64；`codex-cli 0.149.1`；模型参数沿用本机配置 `gpt-5.6-terra`。只实际调用这一种容器客户端，没有声称验证五种镜像或比较模型优劣。

输入为基线受 Git 跟踪文档的导出快照；不含书籍、宿主配置、旧会话与子模块源码。题目明确子模块仅有占位，不要求核验快照中缺失的源码。认证单文件只读挂载，在 tmpfs 中形成临时副本；没有挂载完整用户目录，也没有恢复原实验记忆服务。

| 尝试 | 条件与实际结果 | 判定 |
| --- | --- | --- |
| B1 | 默认 Docker 网络未使用宿主回环代理；请求反复超时，240 秒限时退出 124，无文档回答 | Failed（运行环境），不计阅读得分 |
| B2 | 使用宿主网络与既有代理后模型已响应；CLI read-only sandbox 的首次工具执行报 `bwrap: No permissions to create a new namespace` | Failed（工具环境）；CLI 退出 0 仍不能记为任务通过 |
| B3 | 使用同样只读容器边界，改为 CLI `--sandbox danger-full-access`，避免不被容器允许的嵌套 namespace；3 次文件读取命令退出 0，完成回答 | Passed（8/8 核心问题） |

文件隔离由 Docker 只读根目录、只读 `/workspace`、非 root、cap-drop 和 tmpfs 提供；CLI 第三次没有再提供内部 sandbox。宿主网络并非网络隔离，仅用于已有代理。此处不能笼统称为“全隔离”。

实际调用核心参数：

```text
codex exec --ignore-user-config --ignore-rules --ephemeral --json
  --skip-git-repo-check --sandbox danger-full-access
  --model gpt-5.6-terra --cd /workspace -
```

原理依据与限制见 [R-20](../reference/codex-non-interactive.md)。认证材料不入库，实验记录也不包含其值。源镜像默认实验入口需业务身份并接入共享记忆；本轮直接调用镜像内 CLI，防止那套实验状态干扰本轮观察。

保留实际 [容器输入](evidence/0002-container-prompt.txt) 与从 B3 JSONL 最后一条 `agent_message` 提取的 [完整最终回答](evidence/0002-codex-answer.txt)（仅去除行尾空白并补末尾换行）。回答中的 `/workspace/` 是容器快照路径；行号对应 `affbff9`，不是修正后的当前文件。工具命令轨迹显示只读取基线文档，未请求查看凭据或工作目录之外文件；CLI 本身会读取认证，这不属于读者资料。

主 Agent 对照基线核查 Q1～Q8 均正确。读者 B 特别指出无法在无 Git 历史/子模块源码的快照里独立确认 `affbff9` 与历史基础提交 `7b45c64` 的关系，以及当时子模块恢复情况。这是快照范围限制，不是文档内容错误。A 能查本仓 Git，B 只读导出快照，二者不能用来做模型能力排名。两个读者的结果只说明这组明确提问可回答，不代表自动发现所有维护任务。

## 本轮静态复核

仍使用 REP-0001 中的普通检查方法，只在本轮执行时将验收来源范围改为 R-00～R-20；不改写旧文档中的历史代码。以下命令已执行，且不安装任何包：

```bash
python3 - <<'PY'
from pathlib import Path
import subprocess
record = Path('docs/reproduction/0001-reference-foundation.md').read_text(encoding='utf-8')
script = record.split("python3 - <<'PY'\n", 1)[1].split('\nPY\n', 1)[0]
assert script.count('range(20)') == 1
script = script.replace('range(20)', 'range(21)')
subprocess.run(['python3', '-c', script], check=True)
PY

git diff --cached --check
```

读取的是仓库内已审阅代码段；它是当前有限文档布局的复核命令，不是通用解析器或产品 API。文件链接存在、12 个固定子模块一致和来源编号范围检查仍分别核对；语义引用由 review 判断。

容器结束后，另把导出快照的 42 个普通受跟踪文件逐个与 `git archive affbff9` 对照，全部字节一致，说明本轮读取未修改基线材料。

最终本地复核 **Passed**：39 份 Markdown、178 处本地文件链接、21 个来源条目、12 个固定子模块，缺失目标 0；工作区及暂存差异格式检查通过。原始输入和入库题目内容一致，B3 最终回答仅按已声明方式整理空白，检查一致。未新增依赖或产品代码。
