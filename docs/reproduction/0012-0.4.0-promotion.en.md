# 0.4.0 registry acceptance and promotion

OIDC workflow [34434623009](https://github.com/psiQAQ/planweft/actions/runs/34434623009) published `planweft@0.4.0` from `master@f0ca3200f53ce56e0d122dd5241f233648ca9459` to npm `next`. Its build, complete tests, exact-artifact check, schema-3 prepublication gate, and provenance publish all passed.

The archive downloaded from the official registry has SHA-256 `e611338a619adabb0ba943d75460a01d83e4670dbe7d69f5d1050a1c1467c132` and is byte-identical to the reviewed archive. Registry SHA-512 integrity and SHA-1 also match. At acceptance time, `next=0.4.0` and `latest=0.4.0-rc.1`, so this record does not claim promotion is complete.

## Five-host remote results

Codex, Claude, Pi, OpenCode, and DSH each downloaded the same official-registry bytes and passed installation, doctor, same-version update, content verification, and removal in locked containers with isolated profiles. Pi RPC, OpenCode debug, and DSH compose/boot used fresh processes for native discovery. Additional Codex and Claude checks started separate credential-free host processes after installation and update; each native plugin list found exactly the intended registration. Every container was removed after ownership-label verification, and successful npm/bootstrap caches were cleared.

These fresh-process checks do not call a model and do not prove hook execution or model-context delivery. The five-host actual-model Skill reads remain the single bounded prepublication runs; no model retry was added.

The full RC15→stable→RC15→stable remote round trip was not repeated. As planned, `candidate_to_release`, `release_to_candidate`, `candidate_to_release_again`, and each host's `native_update` use the final stable archive's deterministic lifecycle, the RC15-to-stable per-file manifest, and an independent reuse review. Stable removal, native installation/discovery/removal, and fresh-process loading use new evidence from this run. The separately observed same-version update is not presented as cross-version `native_update` evidence.

## Promotion boundary

`evidence/0010/planweft-0.4.0-registry-acceptance.tar.gz` contains 94 redacted results/logs. Its manifest covers every member and every SHA-256 matches; the privacy scan found no personal path, authorization header, private key, or common npm/GitHub token. `evidence/0010/planweft-0.4.0-registry-proof.json` binds registry digests, dist-tags, source commit, and publish workflow.

npm `latest` may move to `0.4.0` only after independent promotion review, the complete 68-result attestation set, `check-release-gate.py --promotion`, and post-commit CI all pass. The Git tag and GitHub Release remain pending until after promotion.
