# 0.4.0 stable prepublication acceptance

This record binds the single, not-yet-published `planweft-0.4.0.tgz`. The archive was built from clean content commit `aa23df40f9ec8eaed05aa4fbf6f4f0011709995b` and has SHA-256 `438f164a065e2b57469910580baee3c00aaeac92f1c2c831d1223343bfdb7e4c`. Subsequent commits may add only acceptance material excluded from the npm archive; the archive must be rebuilt and proven byte-identical before publication. This record does not claim that npm publication or the GitHub Release is complete.

Ten exact-package preflight/lifecycle cases passed across the five hosts. All five explicit Skill-reading runs used the same exact archive and passed. The Codex and Pi maintenance and cold-reader runs used distinct sessions, and each cold reader received only the final project snapshot bound by its digest. Pi explicit and auto used the same host, CLI, model, task, and permissions; both maintenance-to-cold-read chains passed, so both Pi adoption modes are supported in 0.4.0.

RC15 evidence is reused only where a per-file manifest proves that the relevant target-package inputs are unaffected. Exact artifacts, final installation and removal, user-file protection, and actual Skill reading all use fresh `0.4.0` evidence. Historical reproductions, checkpoints, and failures were not rewritten.

## Known limitations

`LIMIT-CODEX-TRACE-INCOMPLETE`: the predeclared Codex gate-enabled/disabled pair retains two unmodified `Failed` results. The disabled case did not enter the gate; the model returned only `STOP_PROBE`, made no tool call or extra continuation, did not change the project, and completed its session, uninstall, and container cleanup normally. Its native trace nevertheless ended with an unfinished syscall at EOF, so `trace_complete=false`. The enabled trace is complete and attributes the gate reads, but the incomplete negative control prevents the paired assertion from passing. The result is not rewritten to Passed and no additional model retry is performed. It limits the experimental real autonomous/gated stopping claim; it does not negate the passed offline cap/stall/disabled regressions or supported core capabilities.

The Claude, OpenCode, and DSH automatic maintenance, cold-read, context-injection, recovery, and real stopping scenarios remain `Not Run` under this release's bounded model budget rather than being repeated to pursue an all-green result. Their historical results and limitations remain in force. Official-registry lifecycle, new-session loading, and promotion review must be produced after publication to `next`, so they remain `Not Run` at the prepublication stage.

## Evidence and gate

- `evidence/0010/planweft-0.4.0-prepublication-runs.tar.gz` contains exact-package lifecycle, five-host Skill reading, Codex/Pi workflows, and the original Codex pair results. Maintenance and cold reads also have distinct attachments so one digest cannot stand in for both phases.
- `evidence/0010/planweft-0.4.0-local-checks.tar.gz` contains the complete Python, `npm run check`, build, and privacy-check logs.
- `evidence/0010/planweft-0.4.0-rc15-manifest-diff.json` binds RC15 and target archives file by file and records affected checks and the reviewer.
- `release/acceptance.json` uses schema 3. The gate computes `release_blocking` from `release/support-policy.json`; any required non-Passed result blocks, while experimental non-Passed results require an attachment, reason, and public limitation ID.

Before publication, independent prepublication review, the final gate, Linux/Windows/macOS Check on the same final commit, and a byte-identical archive rebuild must complete. After publication to `next`, the package must be downloaded from the official registry, checked for byte and integrity identity, and exercised through five-host remote installation, discovery, doctor, new-session loading, and removal. Only a subsequent promotion review and gate may authorize moving `latest` and creating the `v0.4.0` GitHub Release.
