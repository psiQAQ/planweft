# ADR-0004：本轮暂缓产品 CLI，保留只读检查候选

状态：Accepted（本轮范围决定）；日期：2026-09-07；需求：REQ-01、REQ-04、REQ-06；实验：[REP-0002](../reproduction/0002-handoff-maintenance-baseline.md)。

## 问题与依据

交接基线目前暴露的是状态措辞和验证范围可更清楚，没有证明必须改变文档格式或自动生成上下文。容器的网络和嵌套 sandbox 问题属于执行环境。旧检查器的固定来源数量用于当时快照，不能因增补一篇资料后断言变化便将其视作产品缺陷。

独立新读者方法参考 P-06 `Stage 3: Reader Testing`；先用文档保存状态参考 R-04；可机械检查的约束参考 R-01，但 R-01 没有证明本项目需要专用 CLI。具体实验和限制以 REP-0002 为准，不将单次回答推广为所有项目均已可靠。

## 备选与决定

| 方案 | 收益 | 代价 / 现有证据 |
| --- | --- | --- |
| 沿用 Markdown/Git 与明确范围的检查命令 | 能完成本轮维护，保持现有路径和历史 | 仍靠人工/Agent 判断语义与更新范围 |
| 建立只读文档检查入口 | 可集中报告断链、来源目标缺失、gitlink 不一致 | 现有命令已覆盖部分；尚无跨任务重复负担或漏检数据来证明独立产品收益 |
| 立即增加自动写回、索引库或 hooks | 可能减少后续手工操作 | 本轮没有对应必要性和收益验证，会增加权限、状态与维护成本 |

本轮选择第一项。第二项为下一次选型的首要候选，仅命名其职责，不确定命令名或承诺功能。第三项继续保持未实施。

## 后果、确认与重新讨论条件

完成当前文档修正、引用更新、依据 review 和相关问题回测。保留人工语义判断；状态清晰不等于文档已经实现自动更新。

出现可重复的漏检、重复核对成本或多个项目需要相同检查时，记录复现场景，比较已有检查工具与当前命令，再为最小能力建立规格和计划。只有读文件、报告问题的原型通过正常及破坏样例、Linux/Windows 验证后，才扩展写入能力。用户新的明确需求也可以重新开启此决定。

本轮没有产品原型，因此双平台产品测试与自身体系迁移为 Not Run；不以实验完成作为切换条件已全部满足。
