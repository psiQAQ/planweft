# 计划选择与初始化

[简体中文](plan-selection.zh.md) | [English](plan-selection.md)

任何初始化之前都先执行主 Skill 的范围判断。阅读、诊断、宿主规划模式、简单任务、禁止新增记录或明确要求旧计划继续保持权威时，不初始化。本说明解释包内已有的 PWF 脚本，不添加自动写入 hook。

## 解释实际返回值

使用宿主提供的 Skill 绝对路径，只读取相关项目文件及已安装脚本接口。定位资源不需要宿主设置、安装记录、凭据或旧会话。

Shell 解析器拒绝选择器时也会返回 0，必须结合输出、本任务允许使用的绑定变量及项目文件判断：

- 非空 `PLAN_ID` 是绑定。绑定存在而解析结果为空时是拒绝，不能初始化另一个任务代替它。
- 非空 `PWF_PLAN_ROOT` 必须是已存在、已授权的项目绝对根目录，不是 `.planning` 目录。无效或超出范围的绑定需纠正；不能悄悄清除绑定以切到别的计划。
- 没有绑定时，有效的 `.planning/.active_plan` 指向当前所选计划。多个命名计划没有明确任务选择时，先确定归属，不因解析器返回最新目录就擅自采用。
- 没有被拒绝的绑定且输出为空时，可能采用 legacy 根布局；已有根 `task_plan.md` 时读取它和相邻记录。
- 已授权任务既无所属命名计划，也无根 PWF 计划时，执行初始化。未设置 `PLAN_ID` 是新任务的正常起点。README 指向旧任务记录只提供背景；只有明确要求它继续保持权威，才触发主 Skill 中的例外。

## 在正确位置执行包内初始化器

英文 canonical Shell 脚本要求 Bash。传入任务名时，它在**工作目录**下创建 `.planning/<date-slug>/`、写入 `.planning/.active_plan`，并打印 `PLAN_ID`；它不会自动切换到 `PWF_PLAN_ROOT`。运行前确认工作目录就是绑定且已授权的目标项目；后续操作保存并使用实际打印的 ID。

上游 PowerShell、本地化 legacy 及较旧的宿主专用初始化器（如 standalone Mastra 副本）在工作目录创建 `task_plan.md`、`findings.md`、`progress.md`，不返回命名计划 ID。使用实际创建的文件；独立任务需要隔离时采用明确分配的 worktree。不要虚构 `-PlanDir` 参数或宣称所有 `.sh`/`.ps1` 都支持命名计划。包内没有对应解释器脚本时，使用其已有且有文档说明的脚本。

脚本的 skip-existing 分支保留已有记录。所属任务只缺一份记录时，核对脚本接口，或将缺失模板复制到该任务目录；不要再次运行命名初始化器，另建竞争任务。初始化后检查实际路径，按当前任务及有时间标记的旧观察填写记录，再仅将旧动态状态入口替换为相对链接；保留历史与批准需求。

这些契约来自固定 PWF v3.17.0 的 `resolve-plan-dir.sh` 绑定保护、canonical `init-session.sh` 命名分支，以及本说明旁随包分发的 PowerShell/本地化初始化器。详见[英文对应说明](plan-selection.md)。
