# Overlay assembly contract

These files are local extension sources, not another Skill implementation. The build retains the upstream Skill/runtime and generates every distribution from the same pinned source plus this overlay.

1. Insert `workflow.md` immediately after each main Skill's YAML frontmatter, before the upstream body. Rename the main Skill to `project-docs` and set its description to automatic matching for substantive implementation, maintenance and continuation of documented work; state that reading and planning-only tasks remain read-only. Do not carry forward the 0.1.0 project-opt-in requirement. Localized main Skills can share this English precedence section while retaining their upstream localized body.
2. Copy `references/evidence.md` to `references/evidence.md` next to each main Skill, including standalone Skills. The workflow link is relative to that installed Skill.
3. Append `templates/task_plan.append.md` to `templates/task_plan.md`, `task_plan_autonomous.md` and `analytics_task_plan.md` when present. Append `findings.append.md` to `findings.md` and `analytics_findings.md`, and `progress.append.md` to `progress.md`. Preserve upstream headings, phase order, `**Status:**` literals and original content. Append exactly once during generation from pristine sources, never repeatedly to generated files. The fragments introduce no phase, status token or checkbox that changes runtime completion counts.
4. Upstream ordinary `init-session.sh`/`.ps1` initializes compact embedded records rather than copying ordinary template files. The workflow therefore instructs the Agent to add only useful fields after initialization; do not claim the initializer automatically uses these expanded templates. A build that patches embedded initialization must separately test both new-file creation and preservation of existing files.
5. `README.md` is self-contained package-level explanation material. Keep it available alongside adapter-specific installation/compatibility instructions, avoiding replacement of needed native activation details.
6. These extension files do not choose the command alias map. Apply the build's single identity mapping to all retained upstream implementation, command and install paths; preserve upstream links and attribution as source identity. The extension assumes only `project-docs`, `pd-` helper commands, `pd_` OpenCode tools and unchanged PWF environment/disk protocols.

Verify all installed reference links, descriptions and fragment counts; run parser tests against expanded templates; distinguish those checks from actual Agent behavior validation.
